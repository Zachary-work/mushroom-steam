Get started · Server

A one-time setup. The server only pairs people and signs relay credentials — no video ever passes through it. A Raspberry Pi is plenty.

★ What the server actually does

mushroom steam is peer-to-peer: gameplay video travels directly between the two PCs. The server you host does only the small jobs needed to introduce them.

No media passes through the signaling service — it only introduces the peers.

Two jobs, one small server:
  • Signaling — brokers the WebRTC handshake (SDP + ICE) over a single TLS WebSocket and pairs people by room code. No media passes through it.
  • TURN credentials — signs short-lived coturn credentials so tough-NAT pairs can relay video as a last resort. (Even then, coturn relays the media — the signaling service itself never does.)
Access is gated by wss:// and a shared app secret, so strangers can't use your server.

✓ What you need

A Pi / Linux box Docker + Compose A router you can port-forward A free DuckDNS name

No fixed IP? That's normal at home — DuckDNS gives you a free hostname that always points at your current address.

1 Get the code & Docker

Everything below happens on the server (e.g. ssh you@your-pi). The full reference is in server/README.md.

# Install Docker if you don't have it
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # then log out/in

# Clone the project
git clone https://github.com/Zachary-work/mushroom-steam.git
cd mushroomSteam/server

2 A stable address (DuckDNS)

Create a free subdomain at duckdns.org (e.g. mushroom → mushroom.duckdns.org) and copy your token. Keep it pointed at your home IP with a cron job:

( crontab -l 2>/dev/null; echo '*/5 * * * * curl -s "https://www.duckdns.org/update?domains=mushroom&token=YOUR_TOKEN&ip=" >/dev/null' ) | crontab -

3 Port-forward on your router

Forward these from your router to the Pi's LAN IP:

PortProtocolUsed by
8443TCPsignaling (wss) — or whatever port you set
3478TCP and UDPcoturn TURN relay
49152–65535UDPcoturn relay media range (optional, improves reliability)

4 TLS certificate (for wss://)

Get a free Let's Encrypt cert for your DuckDNS name. DNS-01 avoids opening ports 80/443:

# Using acme.sh with the DuckDNS DNS-01 challenge
export DuckDNS_Token=YOUR_TOKEN
acme.sh --issue --dns dns_duckdns -d mushroom.duckdns.org

# Install the cert where Compose mounts it (server/certs/)
mkdir -p certs
acme.sh --install-cert -d mushroom.duckdns.org --ecc \
  --key-file       "$PWD/certs/privkey.pem" \
  --fullchain-file  "$PWD/certs/fullchain.pem" \
  --reloadcmd       "docker restart mushroom-signal"

Why the reload hook? When the cert auto-renews, it restarts the signaling container so it picks up the new cert.

5 Configure coturn (the relay)

Edit server/coturn/turnserver.conf and set a long random static-auth-secret plus your public IP as external-ip. Remember that secret — it must match the next step.

6 Configure the signaling server

cp config.example.json config.json
nano config.json

Set at minimum:

KeyValue
secretA long random string — the app must send the same one.
tls.cert / tls.keyContainer paths: /certs/fullchain.pem and /certs/privkey.pem.
turn.secretMust equal coturn's static-auth-secret from step 5.
turn.urlsturn:mushroom.duckdns.org:3478?transport=udp (and …tcp).

Generate strong secrets: openssl rand -hex 24 gives a good secret and turn.secret. Every key can also be supplied via an env var (e.g. MS_SECRET, MS_PORT) — env wins over the file.

7 Launch

docker compose up -d --build      # start signal + coturn (auto-restart on boot)
docker compose logs -f signal     # follow signaling logs

Confirm it's alive — from anywhere:

curl -k https://mushroom.duckdns.org:8443/health   # → ok

Now point the app at wss://mushroom.duckdns.org:8443 with the same secret. Continue to Get started · App →

⚡ LAN-only quick test

To try it on a single network without certificates or port-forwarding, omit the tls block so the server runs plain ws://, then point both apps at ws://<pi-lan-ip>:8443 with the shared secret.

LAN only. Never expose ws:// to the internet — it's unencrypted. Use wss:// with a real certificate for anything beyond your LAN.

? Troubleshooting

The app says “Server rejected the app secret.” The App secret in the app doesn't match secret in the server's config.json. They must be identical (case-sensitive).
“Could not reach the server.” Check curl -k https://YOUR-HOST:8443/health returns ok. If it works on the Pi but not externally, your port-forwarding (8443) isn't reaching the Pi, or DuckDNS isn't pointed at your current IP.
Cert / TLS errors in the app The URL host must exactly match the certificate name (mushroom.duckdns.org, not the raw IP). Re-check tls.cert/tls.key paths and that docker restart mushroom-signal ran after issuing the cert.
Connects on LAN but not over the internet Verify port-forwarding (8443 + 3478), and set external-ip in turnserver.conf to your public IP. Test TURN at the Trickle ICE sample — add turn:mushroom.duckdns.org:3478 and you should see a relay candidate.
Useful server commands 
docker compose logs -f signal     # signaling logs
docker logs mushroom-coturn       # TURN logs
docker compose restart            # restart both
docker compose down               # stop
